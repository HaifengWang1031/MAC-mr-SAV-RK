# 本机 MPI 并行求解器

本实现面向单个算例的空间并行；一个时间步由所有 MPI 进程协作完成。时间顺序仍为原 SDIRK2 / SDIRK2-mr-ccSAV，没有压力校正分裂。

## 环境

原串行环境继续支持 `uv sync --locked`。并行依赖作为 `mpi` extra 管理。PETSc 和 MPI 是本机原生依赖，服务器需用当地相互匹配的安装。

macOS 使用 Homebrew PETSc 3.25.5 / Open MPI；先检查已有安装，安装时禁用自动清理：

```sh
HOMEBREW_NO_AUTO_UPDATE=1 HOMEBREW_NO_INSTALL_CLEANUP=1 HOMEBREW_NO_AUTOREMOVE=1 brew install petsc
uv python install 3.12
uv venv --python 3.12 --managed-python
PETSC_DIR="$(brew --prefix petsc)" uv sync --locked --extra mpi
```

不要把 Conda 的 MPICH 与 Homebrew Open MPI 混合。若曾用错误的编译器/库路径构建 petsc4py，需要在干净的 uv CPython 环境中清除该绑定的构建缓存并重建。所有 MPI 进程必须使用同一个 Python 和 PETSc 安装。仅设置进程数不会把原 SciPy 矩阵变成分布式矩阵。

## 数据和算法

沿 y 方向将网格分成连续条带。每个进程只持有自己的 u/v 面值、压力单元、稀疏矩阵行和相邻行 halo。速度编号在每个进程内先 u 后 v，全局按进程拼接。非线性计算用 PETSc Scatter 交换必要的邻域值，不 gather 完整速度。全局场只在明确输出/对照时集中到 rank 0。

速度块 L=mI+κK。保持 G=−Dᵀ，并采用与串行基准相同的压力定标：删去最后一个压力自由度及相关的一个散度行，解后另检查全部散度行，输出时平移到零均值。外层为 FGMRES；下三角块预条件器使用 PETSc GAMG 近似 L⁻¹，压力近似逆为 mQ⁻¹+κI，其中 Q 是同一压力定标下的 MAC Poisson 矩阵，Q⁻¹也用 GAMG。这个近似不是无滑移边界下精确的 Schur 逆；外层迭代纠正其误差。

固定步长重复利用矩阵和 AMG 层次，给定步长采用有上限的 LRU 缓存。块内 AMG 不作为独立时间分裂。用户可调完整系统的容差和迭代上限，失败必须显式报告。当前条带布局适合本机与适量进程验证，不宣称其可扩展到任意数量节点；二维域分解和并行 HDF5 属于后续工作。

## 已验证的规模与限制

2026-09-21 在本机（10 核，24 GB，上文列出的 PETSc 3.25.5 / Open MPI 5.0.10）实测。配置为 `decay`、ν=0.1、dt=1e-3、SDIRK2、固定步长，见 `experiments/parallel_ns/configs/ladder_{64,128,256,512}.json`；对照组是同一配置的原串行 SciPy/SuperLU 直接法（`experiments/decay/run.py`）。总时间为进程级墙钟，每解耗时按每步两次线性求解折算。

| 网格 | 步数 | 直接法总时 | 并行 n=1 / 2 / 4 | 直接法每解 | 并行每解（n=4） | FGMRES 迭代数 |
|---|---|---|---|---|---|---|
| 64² | 10 | 0.06 s | 0.27 / 0.19 / 0.17 s | 1.0 ms | 3.5 ms | 22 |
| 128² | 10 | 0.46 s | 1.64 / 1.19 / 0.43 s | 5.0 ms | 13.6 ms | 23 |
| 256² | 10 | 3.38 s | 5.70 / 4.30 / 5.05 s | 25.5 ms | 233 ms | 27 |
| 512² | 5 | 32.8 s | 12.9 / 9.8 / 7.9 s | 151 ms | 587 ms | 29 |

**迭代数与网格无关**（22→29，自由度 ×64），AMG 预条件达到了设计目的：同为二维压力算子，CG+Jacobi 在本机需要约 700 次迭代才到 1e-3。

**但每次线性求解直接法仍快 3–7 倍**（512²：398 ms 对 151 ms）。

**求解时间的实际分布（已仪器化，见 `manifest.metrics` 的 `velocity_precond_seconds` / `pressure_precond_seconds`）。** 早期把几乎全部时间归给 GAMG 的说法是错的：块预条件只占求解的 24–81%，剩下的是矩阵-向量乘、Krylov 正交化与嵌套向量/Python 开销。256²/n=2 实测：总 189.9 ms/解，速度块 1.01 s、压力块 0.50 s，预条件仅占 40%。

**外层 Krylov 方法是一个便宜的杠杆。** FGMRES 默认 restart=60，正交化成本随迭代数平方增长（256²/n=2 时非预条件部分 4.23 ms/迭代）。换成 BiCGStab（`-ksp_type bcgs`，每迭代成本固定）：

| 配置 | 网格 / 进程 | 迭代数 | ms/解 | 预条件占比 | 总时 |
|---|---|---|---|---|---|
| FGMRES(60) | 256² / 2 | 27 | 189.9 | 40% | 4.99 s |
| **bcgs** | 256² / 2 | **14** | **113.2** | 72% | **3.48 s** |
| FGMRES(60) | 512² / 4 | 30 | 605.2 | 46% | 7.34 s |
| **bcgs** | 512² / 4 | **16** | **398.0** | 73% | **5.22 s** |

即 BiCGStab 快 1.5–1.7×，512²/n=4 上比串行直接法快 **6.3×**（5.22 s 对 32.8 s）。默认仍保留 spec 确认的 FGMRES；BiCGStab 通过 `PETSC_OPTIONS=-ksp_type bcgs` 启用，正确性已由 2/4 进程的测试确认。

**因此 512² 上并行胜出的原因仍主要是一次性成本**：直接法需要 30.5 s 分解与 4.48 GB 峰值内存，并行只需 0.3–0.5 s GAMG 建立与 0.86 GB/进程。据此：

    512² 直接法        ≈ 30.5 + 0.302·F 秒      （F 为步数）
    512² 并行 n=4 (bcgs) ≈ 1.24 + 1.044·F 秒
    交叉点 F ≈ 39 步

即当前实现只在「大网格 + 短运行」下更快；在长积分上直接法仍约快 3.5 倍。

**已试过且行不通的方向（不要重试）。**

- `-pres_pc_gamg_type geo`（几何粗化）：**失败**，`PCSetUp` 报 PETSc error 77。**即使给 PC 挂上匹配的 `DMDA` 也一样失败**（隔离测试：`agg` + DM、`agg` + 零空间 + DM、带/不带前缀与 `setFromOptions` 均正常，只要换成 `geo` 就报 77）。所以 GAMG 的几何粗化在本机 PETSc 3.25.5 上不可用。
- **给 GAMG 挂 DMDA 本身不带来任何加速**：128² 实测 0.434 ms/次（不挂 DM 0.422 ms），256² 1.85 ms/次（不挂 DM 1.94 ms）。矩阵由 `DMCreateMatrix` 创建、布局与 DM 一致也不行。
- **`PCMG`（真正的几何多重网格）无法直接建立**：`pc.setType('mg')` + `setMGLevels(n)` + `PC.setDM(da)` 在 `KSPSetUp` 报 error 75（2/3/5 层都一样）；加上 `-pc_mg_galerkin` 与逐层光滑子选项后改报 error 83（`KSPSetFromOptions`）。要让它工作还需要显式提供插值/限制（`PCMGSetInterpolation`）或改用 `DMComposite` 重排分块，或换一个带齐相关解算器的 PETSc 构建。
- **结论（2026-09-21）**：`DMDA` 重写的收益**尚未被证实**。已证的只有「挂 DM 没有收益」；几何/V-cycle 变便宜的那一半在 PETSc 层就没走通。继续这条路之前，应先写一个能真正建立几何 V-cycle 的原型（显式插值或 `DMComposite`），并同时量好「单次应用成本」与「单次应用降残差比」两个量——前者决定时间，后者决定外层 Krylov 会多花多少次迭代。与上面所有实验一样，这些都可用 `PETSC_OPTIONS` 重做，且会写入运行身份。
- 弱化速度块预条件（`-vel_pc_type jacobi` 或 `none`）：外层迭代数 27 → 115–119，总时间慢 4.7 倍。尽管速度块 L=mI+κK 在 m≫κ 时接近恒等，块预条件的质量仍依赖它。
- 廉价光滑子（`-pres_mg_levels_ksp_max_it 1` 配合 sor、`agg_nsmooths 0`）：**失败**，撞 300 次迭代上限且散度未收敛。
- 正对照（`-pres_pc_type jacobi`）也失败，这正好证明选项已真正传到内层 KSP/PC。

**多进程效率不足**：256² 上 n=4 慢于 n=2（GAMG 粗层通信占比过高）；512² 才单调（605 → 398 ms/解，n=4 效率 34%）。下一步要压低的是预条件本身的每迭代成本（bcgs 后它已占 73–81%），途径是按上面说的 `DMDA` + `PCMG` 重写，而不是继续调 GAMG 选项。

**内存是这条路线的主要价值**：512² 直接法 4.48 GB，并行 0.86 GB/进程且随 N 线性增长；按填充趋势外推，1024² 的直接法需要 30 GB 以上，本机不可行（外推，未实测）。

**选项与运行身份**：两个内层 KSP 分别使用 `vel_` / `pres_` 前缀，外层 KSP 使用全局前缀，都调用了 `setFromOptions`；`PETSC_OPTIONS` 已写入 `source`，因此换选项会得到新的运行身份，不会与旧结果混用。
